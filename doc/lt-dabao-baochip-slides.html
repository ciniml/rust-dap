01Dabao board / Baochip とは

  • Baochip-1x SoC の評価ボード Dabao($12)

    • 著書『ハードウェアハッカー』(技術評論社)で知られるハードウェアハッカー

    • グリッチセンサ、ECC 保護 RAM、セキュアメッシュ、一方向カウンタ
「OSS で検査可能」= 設計(RTL)が読める × 実物が設計通りか自分で確かめられる

02Baochip-1x の特徴的な構成

CPU コアVexRiscv RV32IMAC + MMU @ 350MHz
メモリ保護MPU ではなく MMU(仮想メモリ)
I/O エンジンBIO: PicoRV コア ×4 @ 700MHz
GPIO 速度BIO トグルレート 最大 25MHz
メモリ4MiB RRAM + 2MiB SRAM(オンチップ)
MCU としては珍しい MMU 搭載
全プロセスが独立した仮想メモリ空間。
Rust の所有権・借用のルールを、
プロセス間でも MMU で強制
BIO = I/O コプロセッサ
RP2040 の PIO 相当。ただし専用SMではなく
普通の RISC-V 命令で書ける

06Xous アプリならではのハマりどころ

USB シリアルは Xous のサービス
USB シリアルはすでに Xous のサービス(別プロセス)として動いており、 アプリからの送受信はそのサービスとの IPC になる。 読みはブロックするが、gdbstub は非ブロック読みを要求(Idle 中にターゲットをポーリングするため)
→ 受信専用スレッドが別コネクションで IPC 待ちし、キューに積む構成に
GPIO 操作はマイクロカーネルなので IPC が必要
GPIO は hal-service が所有し、アプリからは 1 操作 = 1 IPC。
ビットバングのような細かい I/O は BIO に任せる設計思想
→ まずは IPC 越しのビットバング SWD で動かす

09まとめ

  • Baochip = MMU 付き RISC-V + BIO という面白い構成
    • 硬さ(セキュリティ)と速い I/O の両立
  • rust-dap は層分離のおかげで移植コストが小さい
    • 書いたのは Connection / DapTransport / セッションループの3つだけ
  • IPC の遅さは BIO オフロードで解決する(BIO 側は動作、入力側を調査中)
  • BIO はいいぞ! — RV32E で書ける PIO。SWD に限らず「ちょっと賢い I/O」全般に効く
